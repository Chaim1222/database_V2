# החלת תיקוני בדיקת האמינות — 8 באוקטובר 2026

התיקון מטפל בשתי תקלות שאומתו: חסרים שגויים כשקשר בתבנית נמצא בערך שנוצר במכלול, ומשימת העברה של דף אחר שהחזיק בעבר באותו שם.

## מה להריץ דרך GitHub

1. למזג את בקשת המיזוג אחרי שהבדיקות האוטומטיות עברו.
2. ב־Actions להפעיל **הוספת שינויי מסד**, לבחור `main`, ולסמן **להחיל בפועל**. המיגרציה החדשה היא `0036_audit_confirmed_gaps.sql`.
3. אחרי הצלחת ההחלה להפעיל **2. בדיקת תבניות מיון** על `main`. הפעולה בודקת גם ערכים קיימים שנוצרו במכלול וטרם נבדקו. היא קוראת תבניות מהאתרים ומעדכנת קשרים מאומתים; אינה משנה את הסיווג „נוצר במכלול”. אם ריצה נעצרת, אפשר להריץ שוב.
4. לבדוק את התוצאות עם השאילתות למטה. לאחר מכן אפשר להריץ שוב **בדיקת אמינות V1 ו־V2** לדוח השוואה חדש.

אין צורך בבנייה מחדש או בטעינה ראשונית. המיגרציה מסירה מיד את משימת ההעברה השגויה; תשעת החסרים מתוקנים לאחר בדיקת התבניות. הסנכרון השוטף יבדוק מעתה גם תבניות בערכים שנוצרו במכלול שנערכו בחלון.

## בדיקה ממוקדת ב־SQL Editor של V2

כל אחת מתשע השורות צריכה להראות `linked_wiki_id` זהה ל־`expected_wiki_id` ו־`still_missing = false`, כל עוד התבניות המקוריות לא השתנו. זו בדיקה של ממצאי הדוח; אין דרישה שכל הדוח יהיה ללא פערים בזמן שאתרי המקור ממשיכים להשתנות.

```sql
with expected(mech_id, expected_wiki_id) as (values
  (940591::bigint,840992::bigint),(623481,1873477),(964840,1996080),
  (746254,2099928),(910862,2198864),(974662,2259198),
  (975715,2345504),(901532,2402199),(880816,2489540)
)
select e.mech_id, m.title, m.status, e.expected_wiki_id,
       t.wiki_id as linked_wiki_id, c.outcome,
       exists(select 1 from api.v_missing v where v.id=e.expected_wiki_id) as still_missing
from expected e
left join mirror.mech_page m on m.page_id=e.mech_id
left join derived.template_link t on t.mech_id=e.mech_id
left join derived.template_check c on c.mech_id=e.mech_id
order by e.mech_id;

-- אמור להחזיר אפס שורות עבור המשימה השגויה.
select * from api.v_moves where id=1178550 and wiki_id=555733;
```
